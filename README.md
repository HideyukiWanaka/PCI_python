プログラムファイルの説明 (README用)
このプロジェクトは、左右に取り付けられた慣性センサー（加速度計、角速度計）から得られた歩行データを解析するためのPythonスクリプト群です。主な機能として、センサーデータの同期、歩行周期（IC/FO）の同定、歩行トライアルの自動分割、位相協調指数（PCI）およびストライド時間変動係数（CV）の算出を行います。対話的なGUIを提供し、同期パラメータの調整が可能です。
主要ファイル構成:
 * run_gait_analysis.py
   * 目的: 解析パイプライン全体を実行するためのメインスクリプトであり、TkinterベースのGUIを提供します。
   * 主要クラス: GaitAnalysisApp
   * 機能詳細:
     * 指定されたフォルダから最新のCSVデータファイルを自動検索します。
     * Tkinterウィンドウを起動し、初期の同期用信号（加速度など）のグラフを表示します。
     * GUI上のスライダーを用いて、同期処理（ピーク検出）に使用する find_peaks のパラメータ（Height, Prominence, Distance）をユーザーが調整できるようにします。
     * 「同期実行＆歩行周期同定」ボタンを提供し、クリックすると以下の処理を順番に実行します。
       * preprocessing.py を呼び出し、調整されたパラメータでデータ同期を実行。
       * gait_cycles.py を呼び出し、同期されたデータ全体からIC/FOイベントを同定。
       * segment_walking_trials 関数（このファイル内で定義）を呼び出し、IC間の時間差に基づいて歩行トライアルを自動分割。
       * trim_trial_ends 関数（このファイル内で定義）を呼び出し、各トライアルの定常歩行部分（開始3歩、終了5歩を除外）を抽出。
       * pci.py を呼び出し、抽出された定常歩行データからPCIとストライド時間CVを計算。
       * 各ステップの結果（同期データ、定常歩行イベント、PCI/CV結果）をCSVファイルに保存（file_utils.py を使用）。
       * 結果確認のため、IC/FOがプロットされたグラフと、同期済み角速度のグラフ（先頭部分）を別ウィンドウで表示します。
     * 処理中の状態をGUI上に表示し、ボタンの状態（有効/無効）を管理します。
   * 依存関係: tkinter, pandas, numpy, matplotlib, japanize-matplotlib (推奨), preprocessing, gait_cycles, pci, file_utils
   * 実行方法: python run_gait_analysis.py
 * preprocessing.py
   * 目的: センサーデータの読み込み、前処理、および同期を行うモジュール。
   * 主要関数: preprocess_angular_velocity
   * 機能詳細:
     * CSVファイルを読み込みます（指定行スキップ、文字エンコーディング対応）。
     * 期待される列構造に基づいて列名をリネームし、不要な列（Blank）を削除します。
     * 指定された同期用信号（例: _Acc_Y）とターゲット信号（例: _Gyro_Z）を抽出します。
     * 左脚のターゲット信号（角速度）の符号を反転させます。
     * 同期用信号の先頭区間（例: 1000サンプル）に対し、指定されたパラメータ (height, prominence, distance) を用いて scipy.signal.find_peaks でピーク（絶対値最大）を検出し、左右のピークインデックス差からラグを計算します。
     * 計算されたラグに基づき、ターゲット信号全体を時間軸上で揃え（アライメント）、長さをトリミングします。
     * 同期後の時間ベクトルと左右のターゲット信号を含むDataFrame、計算されたラグ、ピークインデックスなどを返します。
   * 依存関係: pandas, numpy, scipy.signal, pathlib
 * gait_cycles.py
   * 目的: 同期された時系列データから歩行周期イベント（IC: Initial Contact, FO: Foot Off）を同定するモジュール。
   * 主要関数: identify_gait_cycles, lowpass_filter
   * 機能詳細:
     * 入力された角速度データ（左右）にローパスフィルターを適用します。
     * 指定された閾値 (swing_threshold) と持続時間に基づき、遊脚期（Swing Phase）の区間を検出します。
     * scipy.signal.find_peaks を用いて、角速度信号の極小値（谷）をICおよびFOの候補として検出します。
     * 検出されたSwing区間、IC候補、FO候補を関連付け、ユーザー指定のアルゴリズム（Swing後最初のIC谷、IC+待機時間後で次のSwing前の最も深いFO谷）に基づいて、各歩行周期のICおよびFOのインデックスと時刻を決定します。待機時間はIC時刻と直前のSwingピーク時刻の差から動的に計算されます。
     * 検出された全IC/FOイベントの情報（脚、サイクル番号、インデックス、時刻）を含むDataFrameと、フィルタリング済み信号、時間ベクトルを辞書形式で返します。
   * 依存関係: pandas, numpy, scipy.signal
 * pci.py
   * 目的: 歩行周期イベントデータから位相協調指数（PCI）とストライド時間変動係数（CV）を計算するモジュール。
   * 主要関数: calculate_pci
   * 機能詳細:
     * 入力された歩行イベントデータ（Trial_ID を含む）から、トライアルごとに処理を行います。
     * 各トライアル内で左右の平均スイング時間を比較し、基準脚を決定します。
     * 基準脚の各ストライドについて、対側脚のICタイミングを用いて位相 (\phi_i) を計算します (360度法)。
     * 全ての有効なトライアルから得られた全ての位相データを用いて、位相の平均絶対誤差 (\phi_{ABS} from 180 deg) と変動係数 (\phi_{CV}) を計算します。
     * 最終的な PCI を PCI = \phi_{CV} + 100 \times (\phi_{ABS} / 180^\circ) として算出します。
     * 同様に、全ての有効なトライアルから得られた左右それぞれの全てのストライド時間を収集し、平均、標準偏差、変動係数 (Stride Time CV) を計算します。
     * 計算結果をまとめた辞書を返します。
   * 依存関係: pandas, numpy
 * file_utils.py
   * 目的: ファイル操作に関連するユーティリティ関数を提供するモジュール。
   * 主要関数: find_latest_csv_file, save_results
   * 機能詳細:
     * find_latest_csv_file: 指定されたフォルダ内で、最終更新日時が最も新しいCSVファイルを検索し、そのパスを返します。
     * save_results: Pandas DataFrameを指定されたファイル名でCSV形式（BOM付きUTF-8）で保存します。保存先のフォルダが存在しない場合は作成します。
   * 依存関係: pandas, pathlib, os
これまでの作成のポイントまとめ
 * 目的: 左右の角速度センサーデータ（5ms周期）の同期と、それを用いた歩行分析（IC/FO同定、PCI算出など）の自動化。
 * 同期手法の変遷:
   * 当初、相互相関を試みましたが、歩行の周期的パターンに影響されやすいため、データ先頭部分の「衝撃」を利用する方針に変更しました。
   * 相互相関を先頭1000サンプルに限定しても改善が見られなかったため、ピーク検出法に移行しました。
   * 単純な最大値検出 (argmax) では、複数回の衝撃があった場合に誤検出が発生したため、scipy.signal.find_peaks を用いてパラメータ（高さ、突出度、距離）を指定してピークを検出する方法に変更しました。
 * インタラクティブなパラメータ調整: find_peaks のパラメータはデータによって調整が必要なため、Tkinterを用いたGUIを作成し、ユーザーが初期信号のグラフを見ながらスライダーでパラメータを調整し、その値で同期を実行できるようにしました。
 * モジュール化: コードの管理と再利用性を高めるため、機能を preprocessing, gait_cycles, pci, file_utils, run_gait_analysis に分割しました。
 * 歩行周期同定: ユーザー指定の文献や記述に基づき、アルゴリズムを選択・実装しました。
   * 最初の文献案から、最終的にユーザーが提示した別のアルゴリズム（Swing検出→IC検出→FO検出）に決定しました。
   * Swing検出の閾値 (swing_threshold) が重要なパラメータであることが判明し、調整を行いました（最終的に100で動作確認）。
   * FO検出前の待機時間を、固定値ではなく「IC時刻 - 直前のSwingピーク時刻」で動的に計算するように修正しました。
 * 定常歩行区間の抽出:
   * 15m x 2往復という課題内容から、分析対象を歩行中の定常部分に絞るため、自動でトライアルを分割・抽出する機能を追加しました。
   * IC間の時間差が閾値（例: 2秒）を超える箇所でトライアルを分割し、IC数が少ない（例: 10以下）トライアルを除外しました。
   * さらに、各トライアルの開始3歩と終了5歩を除外し、より安定した区間を抽出しました。
 * パラメータ計算:
   * ユーザー指定の文献に基づき、位相協調指数（PCI）を計算するロジックを実装しました（基準脚決定、位相計算、\phi_{ABS}, \phi_{CV} からの算出）。
   * 追加要望に基づき、左右のストライド時間変動係数（CV）も計算に含めました。
   * これらの計算は、自動抽出された定常歩行区間のデータ全体を用いて行われます（トライアルごとの平均ではない）。
 * UI/UX とデバッグ:
   * GUI起動時のフリーズ感を軽減するため、ステータス表示とボタンの有効/無効化、update_idletasks の使用などの対策を行いました。
   * グラフの日本語文字化け対策として japanize-matplotlib の導入を推奨・実装しました。
   * 途中で発生した NameError や AttributeError, TypeError などのエラーに対し、デバッグ用 print の追加やコードレビューを通じて原因を特定し、修正を行いました。
   * IC/FO検出結果をグラフ上にプロットして視覚的に確認する機能を追加しました。
以上のステップを経て、インタラクティブなパラメータ調整、自動トライアル抽出、各種歩行パラメータ計算、結果の可視化・保存を行う現在のプログラムが完成しました。
